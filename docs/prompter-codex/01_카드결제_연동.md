# 01. 카드 정기결제 실제로 붙이기 (포트원 V2)

## 지금 상태
화면·서버·Edge Function 뼈대는 다 있다. `prompter/config.js`의 `PORTONE.storeId`·`channelKey`가 비어 있어서
구독 관리 화면에 "카드 결제는 준비 중이에요"가 뜬다. 값만 넣으면 카드 버튼이 살아난다.

흐름: 구독 관리 [카드로 구독] → `billing.startCard(token)` → 포트원 SDK `requestIssueBillingKey`(빌링키 발급 창)
→ Edge Function `POST /issue` {token, billingKey} → 빌링키 확인 + 첫 1,990원 청구 → `pr_card_paid` → 화면 `refresh()` → "프로가 열렸어요".
폰에서 결제창이 페이지를 넘겼다 돌아오면 `?after=card&billingKey=...`로 돌아오고 `billing.finishRedirect()`가 이어서 `/issue`를 부른다.
매달 청구: pg_cron이 하루 한 번 `POST /charge-due`(헤더 `x-cron-secret`) → `pr_card_due()` 목록을 청구 → 성공 `pr_card_paid`(31일), 실패 `pr_card_failed`(3일 뒤 다시, 3번이면 failed).
해지: 손님이 `pr_card_cancel` → status canceled, 다음 청구 안 함, 남은 기간은 유지.

## 1.9.0(11/25)에서 끝난 것 — 다시 하지 말 것
- Edge Function을 포트원 server-sdk 0.19.0 타입·경로에 맞춰 완성: 빌링키 주인 확인(customer.id = 복구 코드 해시), 결제 뒤 `GET /payments/{id}`로 PAID·금액·통화·상점·손님 재확인, 첫 결제 동시 두 번 잠금(`pr_card_claim`), 매달 청구 id를 손님+청구일로 고정(중복 청구 불가), 조회가 안 되면 실패로 적지 않음, 웹훅 Standard Webhooks 서명·5분 창 확인 뒤 포트원 재조회 → `pr_card_refunded`(전액이면 기간 회수+자동결제 멈춤), CORS 허용 주소 목록, 오류 내용 안 내보냄, 크기 제한.
- 포트원에는 복구 코드를 보내지 않는다(`pr_` + sha256 앞 24자). 화면 billing.js도 같은 식.
- 시험: `node --experimental-strip-types --no-warnings tests/prompter-billing.mjs` (가짜 포트원·가짜 DB, 27개). 서버 SQL은 로컬 Postgres로 확인.
- 매일 청구: `supabase/prompter-cron.sql` (비밀은 Vault 이름만 참조).

## (옛) 할 일
1. **포트원 V2 공식 문서로 확인하고 맞춘다** (https://developers.portone.io). 뼈대는 기억에 의존해 썼다. 다르면 문서를 따른다.
   - 브라우저 SDK 주소와 `requestIssueBillingKey` 인자(특히 `billingKeyMethod`, `redirectUrl`, `customer`), 모바일 리디렉션 때 붙는 쿼리 이름(`billingKey`, `code`, `message`).
   - 빌링키 조회 `GET /billing-keys/{billingKey}` 응답에서 카드사·끝 4자리 위치 → `cardLabel()`.
   - 빌링키 결제 `POST /payments/{paymentId}/billing-key` 본문·성공 판정 → `charge()`. 결제 상태가 PAID인지까지 확인.
   - 웹훅 서명 검증(Standard Webhooks) → `/webhook`에서 취소·환불을 `pr_payments.status`에 반영(같은 ext_id 중복 안전하게, 필요하면 SQL 함수 추가).
2. 포트원 콘솔 **테스트 채널**의 storeId·channelKey를 `prompter/config.js`에 넣는다(공개 값).
3. `supabase/functions/prompter-billing/index.ts`를 완성하고, PR 설명에 하진이 할 명령을 적는다:
   - `supabase secrets set PORTONE_API_SECRET=... PORTONE_WEBHOOK_SECRET=... CRON_SECRET=...`
   - `supabase functions deploy prompter-billing --no-verify-jwt`
   - pg_cron 한 줄(하진이 SQL Editor에서, CRON_SECRET 값은 하진이 직접 넣음):
     `select cron.schedule('prompter-charge', '0 1 * * *', $$select net.http_post(url := 'https://wuvqtfvvouweqxbydlqa.supabase.co/functions/v1/prompter-billing/charge-due', headers := jsonb_build_object('x-cron-secret', '여기에 CRON_SECRET', 'content-type', 'application/json'), body := '{}'::jsonb)$$);` (매일 오전 10시 KST)
4. 요금을 바꾸면 `config.js`의 `PRICE`와 Edge Function의 `PRICE`를 같이 바꾼다.

## 끝났다고 볼 기준
- 테스트 채널에서: 카드 등록 → 1,990원 결제 → 프로 열림 → `pr_billing.next_at`을 과거로 바꾸고 `/charge-due` 직접 호출 → 두 번째 결제 → 해지 → 다음 청구 안 됨.
- 폰(리디렉션) 흐름도 한 번 확인.
- anon으로 빌링키를 읽을 길이 없음(SQL 시험), 기프트 키 흐름은 전과 같음.
