# 보안 기준

이 저장소의 모든 앱(하진 비서, /manager/, /prompter/, /studio/, 피그마 플러그인)과 앞으로 만드는 것에 적용한다.
코딩 AI(Claude, Codex)도 이 기준을 지킨다.

1. 비밀 값은 저장소·채팅·이슈·문서에 쓰지 않는다. 화면 코드에는 publishable 키만. secret·service_role·결제 키는 서버 비밀 설정에만 둔다. AI는 비밀번호·멤버 코드를 대신 입력하지 않는다.
2. 서버 표는 전부 RLS를 켜고 표마다 누가 읽고 쓰는지 정한다. 새 표를 만들면 로그인 안 한 사람·다른 팀원·본인 세 자격으로 직접 확인한다(`set local role authenticated;` 로 읽기 확인 포함).
3. security definer 함수는 `search_path`를 고정하고, 함수 첫머리에서 호출한 사람의 권한을 확인한다.
4. 사용자 글·AI 답·외부 데이터는 이스케이프해서 넣는다. `innerHTML`/`html:`에는 `esc()` 또는 `md()`를 거친 값만. 링크는 https만 연다.
5. 로그인·코드 입력·방명록·업로드처럼 누구나 두드릴 수 있는 곳에는 횟수 제한과 크기 제한을 둔다.
6. 개인정보(얼굴 사진·연락처·이메일)는 필요한 만큼만 받고, 어디에 얼마나 남는지 알리고, 지울 방법을 둔다. 공개 링크로 나가는 파일은 링크를 아는 누구나 본다고 가정한다.
7. 돈이 오가는 판단은 서버(Edge Function)에서만 한다. 결제사 웹훅은 서명을 확인한 뒤에만 반영한다. 테스트 키로 끝까지 확인하기 전엔 실결제를 켜지 않는다.
8. 바깥 코드·액션·라이브러리는 공식 출처에서, 버전을 고정해 쓰고 출처·라이선스를 적는다. 새로 넣는 건 하진이 확인한 뒤에.
9. 여럿이 같이 쓰는 키(팀 AI 키 등)는 누가 갖는지 알고, 멤버가 나가거나 새어 보이면 바로 교체할 수 있게 한다.
10. 배포 전: `node tests/secrets.mjs`(비밀 값 검사), `/security-review`, 기존 점검(`node tests/run.mjs`, `node tests/order.cjs`)을 돌리고, 바꾼 것 때문에 동기화·로그인·알림이 깨지지 않는지 확인한다.
11. 되돌릴 수 없는 일(서버 표 삭제, 실결제, 외부 발송)은 하진 확인 후에만 한다. 백업부터 본다.

## 자동으로 도는 것
- `.github/workflows/security.yml`: 올릴 때마다 비밀 값 검사.
- `.github/dependabot.yml`: 자동 실행에 쓰는 액션의 보안 업데이트를 PR로 알림.
- `.claude/settings.json`: 팀원이 Claude Code로 이 저장소를 열면 보안 안내·보안 점검 플러그인이 켜지고, `.env`·`members.sql` 같은 비밀 파일 읽기를 막는다.

## 가입이 열려 있는 이유와 막아 둔 것 (11/25 결정)
- 같은 Supabase 프로젝트를 비서 앱(멤버 코드 첫 로그인), 매니저(메일 가입), 프롬프리에딧(메일 코드 로그인)이 같이 써서 가입을 닫으면 셋 다 깨짐 → 가입은 열어 둠.
- 낯선 계정이 할 수 있는 것: 팀 표·개인 기록(items)·사진 저장소는 멤버 확인(is_active/is_member)으로 막혀 있음. 쓸 수 있는 건 매니저 백업(mg_data) 한 줄뿐이고 5MB(`mg_data_size`)로 제한.
- 새 표를 더할 때: 멤버 전용이면 정책에 is_active()를, 아무 계정이나 쓰는 표면 한 사람당 줄 수·크기 제한을 꼭 같이 넣는다.
